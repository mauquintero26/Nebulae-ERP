  confirmar_recepcion exigía que sku_increments no estuviese vacío

  sin ninguna unidad disponible en inventario.

        raise HTTPException(422, "Sin lineas validas...")

    # True  → hubo ingresos reales de inventario disponible
    # False → todo rechazado/cuarentena/faltante (sin ingresos)

    qty_suma = qty_received + qty_rejected + qty_quarantine

      "La suma (recibida=X + rechazada=Y + cuarentena=Z = N) excede

BLOQUEO 3 — SINCRONIZACIÓN SEGURA DE LÍNEAS POR ID
════════════════════════════════════════════════════════════════════

PROBLEMA:
  PATCH /recepciones/{id} relacionaba items del payload por índice
  posicional (posición 0 → GRL 0, posición 1 → GRL 1, etc.).
  Inseguro: orden diferente en el payload → actualiza línea incorrecta.
  POST /recepciones aceptaba _po_line_id del cliente sin verificar
  que perteneciera a la PEC de esa recepción.

IMPLEMENTACIÓN (erp_compras.py):

  PATCH /recepciones/{id} con body "productos":

    Ruta segura (si algún item trae grl_id):
      1. Construir mapa {grl.id: grl} de las GRL de esta recepción
      2. Para cada item del payload:
         a. Requiere grl_id → 422 si falta en payload mixto
         b. Busca grl = gr_lines_map.get(int(grl_id_req))
            → 422 si no existe ("grl_id no pertenece a esta recepción")
         c. Valida po_line_id si viene:
            → 422 si distinto al de la GRL ("no se puede reasignar")
         d. Valida sku_id si viene:
            → 422 si distinto al de la GRL ("no se puede cambiar el SKU")
         e. Actualiza quantity_received, quantity_rejected, quantity_quarantine

    Fallback posicional (payload sin grl_id):
      → Comportamiento 1:1 posicional preservado para compatibilidad

    Legacy sin GRL (recepción sin GoodsReceiptLine previas):
      → Normaliza primero: crea GoodsReceiptLine con source='LEGACY'
      → Luego regenera snapshot JSON desde las GRL creadas
      → NO actualiza solo el JSON sin crear GRL (corrige el bug original)

  POST /recepciones con _po_line_id en el payload:
    Si _po_line_id viene del cliente:
      → Consulta purchase_order_lines WHERE id = _po_line_id
      → 422 si no existe
      → 422 si pol.pec_id != pec_id de la recepción
        ("po_line_id pertenece a la PEC X, no a la PEC Y")
