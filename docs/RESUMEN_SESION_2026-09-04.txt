  confirmar_recepcion exigía sku_increments no vacío → rechazaba con 422
  cuando todo fue rechazado, en cuarentena o faltante.

IMPLEMENTACIÓN:
  - Eliminada validación "not sku_increments → 422"
  - stock_actualizado = bool(sku_increments)
    • True solo cuando hay unidades reales ingresadas al inventario disponible
    • False cuando todo fue rechazado/cuarentena/faltante
  - Validación por línea: qty_recv + qty_rej + qty_quar <= qty_expected
  - qty_faltante = qty_expected - (qty_recv + qty_rej + qty_quar) en snapshot
  - Estados granulares en snapshot JSON:
    RECIBIDO     → qty_received > 0
    RECHAZADO    → qty_received=0, qty_rejected > 0
    EN_CUARENTENA → qty_received=0, qty_quarantine > 0
    FALTANTE     → qty_received=0, qty_rejected=0, qty_quarantine=0

BLOQUEO 3 — SINCRONIZACIÓN SEGURA DE LÍNEAS POR ID
════════════════════════════════════════════════════════════════════

PROBLEMA:
  PATCH /recepciones/{id} relacionaba productos por índice posicional.
  POST /recepciones aceptaba _po_line_id del cliente sin validarlo.

IMPLEMENTACIÓN:

  PATCH /recepciones/{id} con body "productos":
    Ruta segura (payload incluye grl_id):
      → Verifica cada grl_id pertenece a la recepción (422 si es de otra)
      → Verifica po_line_id si viene (422 si no coincide con el de la GRL)
      → Verifica sku_id si viene (422 si no coincide con el de la GRL)
      → Actualiza la GRL por ID, no por posición
    Fallback posicional (payload sin grl_id):
      → Comportamiento legacy 1:1 posicional conservado
    Legacy sin GRL (recepción creada antes de Fase 1B):
      → Primero normaliza: crea GoodsReceiptLine con source=LEGACY
      → Luego regenera snapshot JSON desde GRL

  POST /recepciones con _po_line_id:
    → Valida que _po_line_id exista en purchase_order_lines
    → Valida que pertenezca a la PEC de la recepción (422 si es de otra PEC)
