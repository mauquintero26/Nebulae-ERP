CORRECCIONES IMPLEMENTADAS
--------------------------

1. create_pec  (POST /api/v1/compras/pedidos)
   Archivo: backend/app/api/v1/erp_compras.py
   - Cambiado: db.add(pec) + db.commit() → db.add(pec) + db.flush()
   - Añadido: bucle que crea PurchaseOrderLine por cada producto del payload.
     Una fila por línea del payload, independientemente del sku_id.
     Campos: pec_id, sku_id, description, quantity_ordered, unit_cost_usd,
             unit_cost_cop, quantity_received=0, source='NATIVE'
   - Razón: prerequisito para enlazar GRL con po_line_id unívoco sin LIMIT 1.

2. crear_recepcion_desde_pec  (POST /pedidos/{pec_id}/recepcionar)
   Archivo: backend/app/api/v1/erp_compras.py
   - Construye mapa FIFO: {sku_id: deque([po_line_id, ...])} desde
     purchase_order_lines ORDER BY id.
   - Por cada producto pendiente: asigna _po_line_id via deque.popleft()
     (correcto cuando hay dos líneas con el mismo SKU).
   - Guarda _po_line_id en el dict del producto (campo interno).
   - Crea GoodsReceipt + db.flush() (obtiene gr.id sin commit).
   - Crea GoodsReceiptLine por cada producto en la MISMA transacción:
       gr_id, po_line_id, sku_id, description,
       quantity_expected=qty_pendiente, quantity_received=0,
       quantity_rejected=0, quantity_quarantine=0,
       receipt_type='FISICA', source='NATIVE'
   - db.commit() al final (GR + todas las GRL en una sola TX).

3. confirmar_recepcion  (POST /recepciones/{id}/confirmar)
   Archivo: backend/app/api/v1/erp_compras.py

   a) BLOQUE REEMPLAZADO: "PROCESAR LINEAS DEL JSON"
      Antes: for prod in (g.productos or []) → acumulaba sku_increments
      Ahora:
        gr_lines = SELECT FOR UPDATE GoodsReceiptLine
                   WHERE gr_id=eninv_id ORDER BY id
        Si gr_lines vacío (recepción legacy sin GRL):
          → Fallback: crea GRL desde g.productos con quantity_received=0
            (NO usa qty_recibida del JSON para crear GRL de fallback)
        Para cada grl en gr_lines:
          → qty_received = grl.quantity_received (si 0, usa quantity_expected)
          → valida negativo
          → valida excedente vs allow_excess
          → grl.quantity_received = qty_received  (in-place, NO DELETE)
          → grl.receipt_type = receipt_type        (in-place)
          → si FISICA y sku_id y qty>0:
              sku_increments[sku_id] += qty_received

   b) ELIMINADO: DELETE FROM goods_receipt_lines ... source='NATIVE'
      Razón: conservar IDs de GRL para trazabilidad, asignaciones y auditoría.

   c) BLOQUE AÑADIDO: "REGENERAR SNAPSHOT JSON DESDE LINEAS NORMALIZADAS"
      updated_products = [dict desde GRL con estado calculado]
      g.productos = updated_products   ← JSON es ahora un SNAPSHOT, no la fuente

   d) BLOQUE REEMPLAZADO: "ESTADO DEL PEC — CÁLCULO ACUMULADO"
      Antes: leía p.productos (JSON) y sumaba sku_increments del JSON
      Ahora:
        Ruta primaria: pol_totals = SELECT SUM(quantity_ordered) FROM
                                    purchase_order_lines WHERE pec_id GROUP BY sku_id
          Si hay pol_totals:
            grl_totals = SELECT SUM(quantity_received) FROM goods_receipt_lines
                         JOIN goods_receipts WHERE pec_id AND stock_actualizado=true
                         GROUP BY sku_id
            qty_acumulada_norm = {sku: recv} + sku_increments actuales
            total_pendiente = SUM(ord - recv) para cada sku en pol_totals
          Si no hay pol_totals (PEC legacy sin PurchaseOrderLine):
            Fallback: lee p.productos (JSON) para totales ordenados
            Acumula GRL previas confirmadas (SQL) o JSON de otras ENINV
            Suma sku_increments actuales
            Calcula total_pendiente
